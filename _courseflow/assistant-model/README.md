# CourseFlow 本地意图分类模型

这是一个**经过训练的轻量机器学习分类器，不是大语言模型**。它判断用户是在问空位、比较课程、查看关注列表、选择学期、了解提醒、了解隐私，还是需要帮助。模型不生成课程数据、不估计未来空位，也不能注册、退课或发送消息。实际数据由应用的数据查询层提供。

Python 标准库负责训练；浏览器中的 TypeScript 使用 CPU 推理。没有模型服务、第三方推理 API、ML 运行库或额外下载。模型 JSON 为 **115,892 bytes（约 113 KiB）**。

## 怎样工作

1. NFKC 归一化、转为小写，将形如 `CS 3100` 的课程代码和年份分别替换为占位符，限制输入前 2,000 个字符。
2. 提取字符 2-gram、3-gram，用 `1 + log(count)` 和平滑 IDF 加权，再将向量长度归一为 1。
3. `train.json` 中的 **198 条有标签示例**形成八种意图。每个意图分别训练中文和英文中心，共 16 个原型；输入与两个语言原型的最大余弦相似度作为该意图的得分。中英混合输入同样可以参与比较。
4. 返回得分最高的意图。覆盖率、相似度、领先第二名的差距或置信评分不足时，回退到 `unknown`。训练集还显式包含域外问题。

`confidence` 是带温度的 softmax **排序分数，不是校准后的正确概率**。`coverage` 是输入 n-gram 出现次数中被训练词表覆盖的比例；常见英文可能具有高覆盖率，但仍然属于未知领域。

```ts
import { classifyIntent } from './classifier.ts';

classifyIntent('CS3100还有位置吗');
// { intent: 'availability', confidence: ..., margin: ..., coverage: ... }
```

返回类型为 `availability | compare | watchlist | terms | notifications | privacy | help | unknown`。分类器本身不执行操作；引擎仍需检查课程格式、课程数量、意图要求、输入范围与写操作限制。**不能把“已分类”当作授权或安全判断。**

## 训练、复现与验证

从此目录运行，需要 Python 3.10+、Node.js 24+，无需安装 Python 包：

```sh
python3 train.py train
python3 train.py evaluate --input development-v1.json --output development-v2-results.json
python3 train.py evaluate --input holdout-v2.json --output holdout-v2-results.json
node verify.mjs
```

训练命令**只读取 `train.json`**，不会读取开发集或 holdout。训练会导出 `../frontend/src/assistant/model.json` 和 `calibration-results.json`。相同环境与训练数据重复生成字节完全一致的模型；`verify.mjs` 检查此项，并检查 318 个输入在 Python 与 TypeScript 之间的一致性、空输入/表情回退、模型大小限制。

阈值由训练集内部完整留一法选择：每折都排除一个训练示例，并重新拟合词表、IDF、两种语言中心。在 450 个预先定义的阈值组合中最大化各类平均召回率；相同时优先未知拒识，然后优先更严格的阈值。最终阈值：

| 检查 | 最小值 |
| --- | ---: |
| n-gram 覆盖率 | 0.10 |
| 最佳原型余弦相似度 | 0.04 |
| 前两种意图的相似度差 | 0.005 |
| softmax 排序分数 | 0.20 |

softmax 温度固定为 0.10。训练内部 LOO 正确 **108/198**，各类平均召回率 **55.3%**，说明少量例句对陌生表达的泛化能力有限。该指标与下面 holdout 的明显差异，也说明小型合成测试非常依赖句子分布。

## 评估过程和真实边界

这些数据是开发助手编写的中英文**合成例句**，没有真实学生对话，没有用户研究，也没有大规模人工标注数据。`holdout-v2.json` 由另一位开发代理独立编写；没有复制训练文本。不要将下列数字写成生产准确率或真实用户满意度。

- **v1 诊断集**：`development-v1.json` 共 58 条。最初采用每类单中心和预设保守阈值，得到 36/58 正确；支持意图仅 20/42 接受正确，域外 16/16 拒识。查看过这份诊断后，它便是开发集，不能继续称为完全盲测集。
- **v2 改动**：训练文本不变，拆分中文/英文原型以减少跨语言中心稀释；阈值只由上述训练内部 LOO 选择，没有用开发集优化参数。相同开发集上得到 50/58；该结果仅用于诊断。
- **v2 新 holdout**：模型及阈值冻结后才评估 56 条独立编写的句子。一次评估得到 **50/56（89.3%）**；支持意图 **39/42（92.9%）**，域外正确拒识 **11/14（78.6%）**。没有根据这些错误再次训练或调整阈值。

已观察到的错误包括：

- 单门课程的“剩余名额”被判为比较；引擎应要求比较至少两门合法课程。
- `Spring 2027` 被通用课程代码正则误当成课程占位符，导致一条学期问题错分。该已知归一化缺陷保留在此冻结评估版本，后续修正应使用新的评估集。
- “对话会不会发给 OpenAI”错分为比较。
- 比较两地天气、解释 Java 继承、要求改变规则读取私信等域外输入，有时被判为业务意图。分类器不是可靠的域外检测器，更不是注入防御系统。
- 原开发集仍有资格判断、注册请求、手机比较的误分类，所以引擎需独立拒绝这些操作。

随机无关字母、空字符串、纯表情会因低覆盖率/低分回退为 `unknown`。常见示例“CS3100还有位置吗”“How many seats does CS 3100 have?”“compare CS3100 and CS3200”“我的关注哪个还有位”“有哪些学期”“如何通知我”“你会保存密码吗”“怎么用”均能得到预期分类；它们是训练示例，不能作为泛化效果证据。

若继续开发，先获得知情同意的实际匿名查询并独立标注；保留全新的测试集，增加困难域外负例，再选择更稳健的模型。不要只把当前错误句子加入训练后重复报告同一份测试准确率。
